not a need to rewrite the application. Fix each contract with a regression test
that fails on the current implementation before changing its owner.

## Order and risk checkpoints

1. Independent test-first slices: subprocess/approval/path safety; browser/Issue
   navigation; schedule persistence/invalid-row isolation; startup/resume/Git
   isolation. Each slice owns its source and dedicated new test files.
2. Integrate scheduler-to-executor CSV source metadata. Local prompt text remains
   user-editable in CSV, not duplicated into SQL; resume refuses a changed or
   missing source instead of executing another prompt silently.
3. Review concurrency, migration defaults, local-only publication boundaries,
   error redaction, and compatibility with existing tests. Do not auto-requeue a
   launched task after restart; explicit safe resume remains required.
4. Run `py -m pytest`, `py -m ruff check .`, `py -m mypy app`,
   `py -m app.main --check-config`, skill validation and Git/secret hygiene.
   Fix regressions before declaring completion.

Settings: no credentials, `.env` changes, or personal-mode enabling is needed.
Issue schedule schema additions must be additive/idempotent with defaults for
existing rows. Tests use temporary databases, CSVs, workspaces and kill-switch
paths, and mocks for external services/processes.

Unknowns: actual installed CLI interactions and live Telegram behavior are not
validated by mocks; disclose these limits. Do not invent new CLI flags to make
unsupported model/effort settings appear supported.

Rollback: keep repairs in focused patches. In this pre-existing dirty tree,
reverse only this task's hunks/new files after inspection; do not reset or restore
whole files. If committed later with authorization, revert the repair commit
rather than resetting the user's branch. Added DB columns can remain unused on
rollback; never delete projects or runtime CSV content to roll back code.
