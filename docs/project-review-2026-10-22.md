## النطاق والنتيجة

راجعت بنية التطبيق، بدء التشغيل وإيقافه وإعادة التحميل، تسجيل معالجات Telegram
وتدفق الواجهة، اختيار المشاريع والمسارات، SQLite وCSV، الجدولة، المشغّل ووكلاء
CLI، الموافقات والاستئناف، خدمات GitHub، الاستخدام الشخصي، والاختبارات وإعدادات CI.
راجعت أيضًا المهارات الموجودة لتحديد ما تحتاجه مهارة خاصة بمعمارية المشروع.

النتيجة: **11 ملاحظة مؤكدة: 5 بأولوية P1 و6 بأولوية P2**. نجاح اختبارات الوحدة
الحالية لا يثبت سلامة التكامل بين هذه المكونات. هذه مراجعة للكود واختبارات محلية
معزولة، وليست اختبارًا حيًا لـTelegram أو الوكلاء أو تدقيقًا أمنيًا خارجيًا شاملًا.

لم أغيّر كود البوت، إعداداته، بياناته، فرعه، أو المهارات السابقة. التغييرات الجديدة
هي مهارة المشروع ومراجعها، ربطها في `AGENTS.md`، وهذا التقرير. التغييرات القديمة
غير المحفوظة في Git بقيت كما هي. لم يُنفّذ commit أو push.

## P1 — يجب معالجتها قبل الاعتماد على التشغيل المستمر

### 1. استعادة المهام المتوقفة لا تعمل عند بدء التطبيق

- المصدر: `app/main.py:55`، `app/main.py:60`، `app/main.py:85`؛ التنفيذ الموجود في `app/runner/recovery.py:73`.

- الأثر: بعد تعطل البوت أثناء مهمة، تبقى حالة المهمة نشطة في SQLite؛ تمنع مهمة جديدة، وتتوقف الجدولة عند فحص المهمة النشطة. الاستئناف يرفضها لعدم وجود علامة الانقطاع.
- الدليل: مسار بدء التشغيل مقابل شرط `JobExecutor.resume_job` وفحص `scheduler.py:86`. الاختبارات الحالية تستدعي خدمة الاستعادة مباشرة ولا تختبر ربطها ببدء التطبيق.
- الإصلاح المقترح: تنفيذ الاستعادة قبل استقبال العمل وبدء المجدول؛ اختبار بدء تشغيل بقاعدة مؤقتة تحوي مهمة يتيمة. لا تعِد تشغيل عمل قد يكون مستمرًا خارج البوت دون التحقق من ملكيته.

### 2. انتهاء المهلة الخارجية قد يترك عملية Agent تعمل

- المصدر: `app/runner/fallback.py:225`؛ `app/agents/codex.py`، الدالة `_run_cli`.
- السبب: `asyncio.wait_for` في الموجّه يُلغي coroutine قبل وصول مهلة العملية الداخلية، ولا يستدعي `agent.stop`. لا تضمن `_run_cli` تنظيف العملية والقارئات عند الإلغاء.
- الأثر: قد تُعدّ المهمة منتهية بينما تواصل العملية تعديل الملفات واستهلاك الموارد؛ تشغيل مهمة أو fallback لاحق قد يؤدي إلى عمليتين على المشروع نفسه.
- الدليل: محاكاة عملية CLI وانتظار خارجي قصير انتهت بـ`TimeoutError` مع صفر استدعاءات لـ`terminate` و`kill`. لم تُشغّل عملية Agent حقيقية.
- الإصلاح المقترح: ملكية واضحة للعملية وتنظيف في `finally` عند timeout/cancellation؛ terminate ثم انتظار محدود ثم kill وانتظار الإنهاء، مع إغلاق مهام القراءة قبل تحرير خانة التشغيل. اختبارات للموجّه مع كل Adapter، لا للـtransport العام فقط.

### 3. قيد المجلدات المسموحة يقبل مجلدًا شقيقًا بنفس البداية

- الأثر: عندما يكون الاستخدام الشخصي مفعّلًا، يمكن أن يمر ملف خارج المجلد المسموح إذا استوفى بقية فحوص التنزيل. هذا ليس تجاوزًا لمصادقة Telegram، بل كسر لحدود الوصول المهيأة.
- الإصلاح المقترح: احتواء `Path` فعلي مع مراعاة Windows والروابط؛ تغطية sibling-prefix والمسارات الداخلية والخارجية. راجع النمط المشابه في مسار Codex API المنفصل أيضًا.

### 4. بصمة الموافقة لا تشمل محتوى التغييرات

- المصدر: `app/runner/approvals.py:185` و`app/runner/approvals.py:315`.
- السبب: البصمة تعتمد على `git status --porcelain` وHEAD والفرع، وليس محتوى diff. وفشل حساب البصمة لا يجعل الموافقة قديمة، أي أن التحقق يفشل باتجاه السماح.
- إعادة الإنتاج: طلب موافقة على ملف معدل، ثم تعديل محتواه مرة ثانية دون تغيير اسم الملف أو حالة Git أو HEAD؛ تبقى بيانات البصمة نفسها.

- الإصلاح المقترح: بصمة فعلية للتغييرات التي ستُعتمد، تشمل staged/unstaged/untracked حسب نطاق الموافقة؛ رفض/تعليق الموافقة عند تعذر التحقق. اختبار تعديل المحتوى داخل الملف نفسه بين الطلب والقرار.

### 5. استئناف مهمة محلية يفقد البرومبت وحدود local-only

- الأثر: الاستئناف بعد انقطاع/نفاد رصيد يفقد الطلب الأصلي وإعداداته، وقد يدخل مسار push/PR بدل الاكتفاء بالتنفيذ المحلي؛ حالة CSV لا تستعيد ربطها بإكمال المهمة.

- الإصلاح المقترح: حفظ عقد تنفيذ قابل للاستعادة وربط آمن إلى البرومبت/جدول CSV، دون فقد الخصوصية؛ اختبار يمنع استدعاء push/PR في كل استئناف لمهمة محلية.

## تحسينات منفصلة عن العيوب المؤكدة

- README وبعض المهارات القديمة تصف أوامر أو مسارات اكتشاف Desktop/فروع لم تعد تطابق التنفيذ. المصدر الفعلي هو registry واستدعاءات الـCLI؛ لم تُنسخ هذه الافتراضات للمهارة الجديدة.
- `psutil` مذكور في `requirements.txt` لا `pyproject.toml`؛ قد تكون ميزات الموارد ناقصة في تثبيت يعتمد على الحزمة وحدها. توجد معالجة لحالة غياب المكتبة، لذلك لا يُسجّل ذلك كتعطل مؤكد.
- راجع طول `callback_data` عند تضمين أسماء مستودعات طويلة؛ Telegram يحده بـ64 بايت.
- لا يزال `main_menu_button()` يولد «✖️ إنهاء» في مسارات أقدم، وهو مخالف لتفضيل المستخدم السابق.
- معظم التغطية الحالية لوحدات منفردة. الأولوية لاختبارات التكامل بين بدء التطبيق/الاستعادة، وإعدادات الجدولة/dispatch، والمتصفح/تأكيد DB، والمهمة المحلية/الاستئناف.
